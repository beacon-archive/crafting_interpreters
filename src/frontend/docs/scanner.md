# scanner

scanner 是扫描器，也叫做词法分析器。

词法分析器以一系列字符的形式接收原始代码，将其分成一系列的块，并解析其隐含的含义，我们称这个整体为标记(词法单元)。这些标记，都是有意义的"单词"或者"标点"，它们构成了语言的语法。


## Lexemes and Token 词素和标记(词法单元，最小的语法单元)

词法分析就是扫描字符序列，将它们归纳为"具有某些含义"的最小序列，每一组序列都被称为词素。词素本身只是原始代码的一个子串，但它也包含了一些其它有用的信息，我们获取词素，并将其与其隐含的信息绑定时，就得到了一个 token。


### token type

在英语语法中，单词被分为名词、动词、形容词、标点符号等。同样地，在编程语言的词法分析中，每个词素都应该被归类到某个**token type**中。如此，后续解析器处理 token 时，不必再去判断 token 的含义，可以直接根据其类型进行对应的处理(调用对应的函数)。

这里的分类方式，是依据其功能来进行区分的，而非其结构组成(正则描述，关键字和标识符有相同的正则描述)。


1. 字面量(Literals): 标识符(IDENTIFIER)、字符串(STRING)、数字(NUMBER)
2. 关键字(Keywords)
3. 运算符(Operators)
4. 标点符号(Punctuation)/分隔符(Delimiters)

在 Lox 中，每一个 token 都有其对应的类型，方便解析器进行后续处理(直接调用对应的函数，不必再分析 token 的含义)。token 主要有如下几类：


### Literals value 字面量

字面量有其对应的词素(字符串，数字或者字符串的文本形式)，为了方便解析器使用，词法分析器需要将这些文本内容转换成运行时对象。

词素都是以文本形式存储的, 无法进行运算。比如说数字 2, 当它以文本形式存储时，如果使用的是 ascii 码存储的话，存储的值是: 32，是无法进行正常的算术运算的。但当它存储在内存中时, 是以二进制形式 ....0010，这样是可以进行正常的算术运算的。因此，我们需要针对字面量类型的词素，解析其运行时对象值。


### Location information 位置信息

对于一个 token，我们应该标记其所在的行号，列数，以及长度，提供的信息越全，后续在使用时，也会反馈给用户更加清晰的信息。




## Regular Languages and Expressions 正则语言和表达式

词法分析器的输入，始终都是字符。从源码的第一个字符开始，分析器就会判断它是哪种词素，然后消耗掉它以及该词素对应的后续字符，并解释其隐含含义，最终输出一个 token。一直循环，直到输入的终点。

每一种词素(注意，不是一个 token type，token type 是依据功能进行分类的)都对应于一个 regex，我们使用这个 regex 来匹配字符。例如，一个标识符的 regex 如下：

```text
[a-zA-Z_][a-zA-Z_0-9]*
```

词法语法: 决定一门语言如何将字符分组为词素的规则。对于词法语法简单的语言，可以称其为正则语言。



### Reserved Words and Identifiers  保留字和标识符

标识符是由下划线或字面开头的一个连续不为空的数字字母下划线组成的字符串，正则表达式的描述:`[a-zA-Z_][a-zA-Z_0-9]*`，一个标识符的 token type 为: IDENTIFIER.

保留字和标识符在结构上是相同的，保留字是标识符的一个子集，只是我们预先设置了一些标识符有特殊用途。对于一个标识符，首先会判断其是否位于关键字集合中，如果位于，那么它的 token type 将会设置为对应的关键字: AND, CLASS...等等，没有就将其设置为标识符。


# idea

当用户的代码在工作时，他们根本不会我们的语言——他们脑子里想的都是他们的程序。通常只有当程序出现问题时，他们才会注意到我们的实现。
编译器或者解析器都是一种实现，我们需要关注它们是如何实现的。


前端的各个阶段都是检测到错误，但是它们不需要知道如何向用户展示错误。在一个功能齐全的语言实现中，可能有多种方式展示错误信息：在 stderr 中，在 IDE 的错误窗口中，记录到文件，等等。
