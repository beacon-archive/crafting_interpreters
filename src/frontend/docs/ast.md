# Representing Code 表示代码

对于一个数学表达式，我们能够快速、正确的计算出其结果，这是因为我们知道算术运算符的优先级。算术运算符的优先级，我们有一种方式可以对其进行可视化：树！

叶子节点是数字，算术运算符是内部节点，各个算术运算符的操作数都对应于一个单独的分支。

当我们需要计算一个算术节点(用树来表示表达式时，其中的运算符节点)的值时，我们首先需要计算其子树的值，也就是说我们需要从其叶子节点遍历到根节点——后续遍历。


基于此，我们也可以将代码(此章只涉及四个基础表达式)使用树结构来表示，语法树(AST)!

就像数学运算表达式一样，我们也需要先定义语法(代码表达式)的内容，优先级。



# Context-Free Grammers 上下文无关语法

在上一章中，我们将字符分为对应的词素的规则，被称为正则语言，但正则语言无法处理深度嵌套的内容。

上下文无关语法是形式化语言的一个重要工具，一个形式化语言需要一个原子片段，它称之为alphabet(字母表)。然后定义了一组(通常是无限)的string(字符串)，这些字符串包含在语法(可行的组合/规则)中，每个字符串都是字母表中的letters(字符)组成序列。

所谓的语法，就是可行的组合或者规则！

目前我们使用的语法有两种：

1. 词法语法(词法分析器): 决定字符如何组合成 token
2. 句法语法(解析器): 决定 token 如何组合成对应的表达式(目前是4种)


形式化语法(规则)的作用就是指出哪些字符串是合法的。



## Rules for grammers 语法规则

我们无法为可能无限长的字符串一一列举出它的可行的语法规则，因此，我们反过来定义一组规则，用这些规则反过来生成对应的字符串。生成的字符串，我们称之为生成式，或推导式，因为他们是推导出来的。

而这些规则，我们称之为生成式。


上下文无关语法的规则，主要由两部分组成，规则的名字，以及它的主体。主体主要两种组成，终止符和非终止符。

终止符就是一个字面量表达式，而非终止符就是另外一个规则的引用，并将其结果放在这里。



## Enhancing our notation 增强符号

在 lox 的表达式中，为了简化语法规则的表示，和正则表达式一样，使用了四种增强符号：

1. | 管道符
2. *
3. ?
4. +
5. ()
